## Stage 1 — 免费体验（零门槛进入）

### 目标
让用户进入游戏后立刻理解「金币有价值」，不需要付费也能玩。

### 实现细节

**1. 新用户金币包**
```json
{
  "type": "welcome_bonus",
  "user": "观众",
  "coins": 100,
  "message": "🎉 欢迎！赠送100金币体验礼物效果！"
}
```

- 新用户首次连接WS时自动发放
- 前端头像旁边显示金币余额 `🪙 100`
- 金币图标闪烁3秒引导注意

**2. 金币展示位置**

```
┌─ Header ──────────────────────────────┐
│ 🐢 CCcat海龟汤          🪙 100  💰充值 │
└───────────────────────────────────────┘
```

- 右上角常驻金币余额
- 点击余额弹出「余额明细」
- 「💰充值」按钮始终可见（但优雅不弹窗）

**3. 免费礼物引导**
- 首次开始游戏后，礼物面板最左边有一个闪烁的「🎁 试试礼物」
- 点击后免费送第一个点赞（0金币）
- 触发揭示后，弹一个小提示：「哇！揭示了一个字！送啤酒效果更爽哦~」

**4. 关键交互流程**
```
1. 用户打开游戏
   → WebSocket 连接成功
   → 后端发送 {"type":"state_sync", "coin_balance":100}
   → 前端顶部显示 🪙 100

2. 用户点击「开始游戏」
   → 游戏开始
   → 礼物面板底部小字提示：「🪙 余额100，试试送个礼物吧！」

3. 用户点击任意礼物
   → 如果金币够 → 直接成功（加动画）
   → 如果金币不够 → 弹出充值面板（非弹窗，侧滑面板）
```

## Stage 2 — 首次送礼（关键突破点）

### 目标
让用户完成「第一次送礼物」的动作，体验「花钱能得到快乐反馈」的闭环。

### 心理学原理
- **沉没成本**：一旦用户送过礼物，他就不再是"纯免费玩家"
- **互惠心理**：送了礼物→游戏给了揭示反馈→用户觉得"值了"
- **蔡格尼克效应**：揭示没完成→想继续送→完成它

### 触发时机

**时机1：游戏首次开始后30秒**
```
条件：用户未送过任何礼物
触发：弹幕气泡上方出现一个浮动提示
文案：「💡 送个啤酒试试？能揭示隐藏的文字！」
样式：半透明浮动小卡片，10秒后自动消失
```

**时机2：猜对一条弹幕「是」之后**
```
条件：用户刚发送的弹幕被LLM判定为「是」
触发：QA气泡发送后延迟1秒，在礼物面板闪烁
文案：「🎯 方向对了！送人气票获取更多提示？」
```

**时机3：弹幕命中揭示后**
```
条件：弹幕中的字命中了汤底实词
触发：揭示动画结束后，礼物面板对应礼物高亮
文案：「🔥 歪打正着！送棒棒糖可以一下揭示整句！」
```

**时机4：防卡死自动揭示后**
```
条件：防卡死自动揭示了一个字
触发：系统消息后跟一个推荐
文案：「⏰ 进度有点慢，送个啤酒快速推进？」
```

### 首次送礼的强化反馈

用户第一次送礼时，反馈要比普通送礼更强烈：

```javascript
// 首次送礼特殊效果
if (userFirstGift) {
  // 1. 全屏闪光特效（金色粒子）
  showParticleBurst('#ffd700', 50);
  // 2. 大号揭示动画（字放大到200%再缩小）
  revealCharAnimated(char, { scale: 2.0, duration: 800 });
  // 3. TTS特殊音效
  playSound('gift_first.mp3');
  // 4. 全屏Toast（停留3秒）
  showToast('🎉 太棒了！你帮助揭示了"' + char + '"！');
  // 5. 邀请继续
  setTimeout(() => showHint('继续送啤酒，每次揭示新字！'), 3000);
}
```

## Stage 4 — 连击消费（付费冲动）

### 目标
利用「已经花了钱→不想浪费→继续花」的心理，制造连续消费。

### 连击UI设计

```
游戏中顶部连击指示器：

  ┌─ 连击 ─────────────────────┐
  │  🔥 x3  下次揭示双倍！      │  ← 数字闪烁
  │  ████████░░░░ 剩余 12秒    │  ← 倒计时条
  └─────────────────────────────┘

  连击状态      颜色     文字
  1-2         灰色     🔥 x{count}
  3-4         金色     🔥 x{count} 1.5x
  5-9         紫色     🔥 x{count} 2.0x 🔥
  10+         红色     🔥🔥 x{count} 3.0x 🔥🔥
```

### 连击触发策略

**策略1：首次连击引导**
```
用户送了第1个礼物(非点赞)
→ 连击指示器出现，倒计时30秒
→ 浮动气泡：「🔥 再送一个触发连击！揭示双倍效果！」
```

**策略2：连击将断提醒**
```
连击≥2且倒计时≤5秒
→ 倒计时条变红闪烁
→ 提示：「⏰ 连击即将中断！快再送一个！」
→ 可以做个半透明「一键续击」按钮
```

**策略3：连击升级庆祝**
```
连击达到3/5/10时触发全屏效果
→ 金色粒子 + 大号文字
→ 「🔥🔥 3连击！揭示效果1.5倍！」
→ TTS语音播报连击
```

### 连击退出策略
- 30秒超时 → 连击重置，显示「💔 连击中段，下次再战！」
- 如果用户隔了很久再送，从1重新开始

### 连击数值设计
```
           效果           额外揭示
1x (1-2次)  标准效果     0
1.5x (3-4次) 效果提升    +1字（啤酒）
2x (5-9次)  效果提升    +2字（啤酒）
3x (10次+)  效果爆炸    +3字（啤酒）+ 全屏特效
```

## 数据指标体系

为了衡量漏斗效果，需要埋点的数据：

| 指标 | 计算方式 | 目标 |
|------|---------|------|
| 金币消耗率 | 消耗金币/获得金币 | >60% |
| 礼物发送率 | 送礼用户/活跃用户 | >30% |
| 签到率 | 签到用户/活跃用户 | >50% |
| 连击触发率 | 触发连击用户/送礼用户 | >20% |
| 充值转化率 | 充值用户/活跃用户 | >3% |
| VIP转化率 | VIP用户/活跃用户 | >1% |
| ARPU | 总金币消耗/活跃用户 | >150金/人 |

## 技术实现注意事项

1. **所有推荐引导都不能打断游戏** → 使用半透明浮动卡片，非弹窗
2. **每种推荐每局只出现1次** → 后端记录 `hint_shown[]` 去重
3. **连击倒计时用前端setInterval** → 精确到1秒更新
4. **金币变动用WS推送** → 后端 `gift_effect` 消息附带余额
5. **充值目前走模拟** → 不接真实支付，但留好接口
6. **数据持久化暂用内存** → 后续迁移到localStorage或SQLite
