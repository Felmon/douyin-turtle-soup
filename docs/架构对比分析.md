## 一、总体对比

### 核心功能对比

1. **弹幕管道**: 架构要求WSS抓包->中继->过滤->轨道A->轨道B
   - 当前: 单进程server.py内置WS处理+LLM API  [OK]
2. **轨道A逐字解密**: 弹幕命中+虚词排除+全文同字揭示
   - 当前: RevealEngine类+handle_danmaku中Track A循环  [OK]
3. **轨道B是非问答**: Qwen三分类(是/不是/是也不是)
   - 当前: 通过LLM API远程调用  [OK]
4. **题库**: 15道题每题配8-12条特化QA
   - 当前: 15道题但specificQuestions字段全空  [WARN]
5. **服务架构**: 微服务拆分(WSS:9876+Qwen:3009+TTS:3006+前端:3110)
   - 当前: 单进程合并已简化但可用  [INFO]
6. **TTS**: Edge TTS+后进先出优先队列
   - 当前: tts-relay.cjs存在但前端用Web Speech API  [WARN]
7. **防卡死**: 3分钟/50条弹幕自动揭示+衰减机制
   - 当前: 已添加后台任务  [OK]
8. **礼物索要**: Qwen根据现场气氛生成话术
   - 当前: llm_gift_solicit函数存在但未被触发  [PENDING]

### 文件级变化

- server.py: 纯游戏引擎 -> 合并服务(游戏+分类+嵌入式前端)
- barrage-relay.mjs: WSS中继(:9876)存在但未启用
- qwen_server.py: 本地Qwen2.5(:3009)存在但未使用(远程API代替)
- tts-relay.cjs: Edge TTS(:3006)存在但有webpack问题
- embedded_ui.py: 新增嵌入式HTML前端(架构文档未预见)
- game_server.py: 被server.py取代成为废弃文件

## 三、服务架构对比

目标架构:
  抖音WSS抓包 -> barrage-relay(:9876) -> game_server(:3010)
                                            +-- qwen_server(:3009)
                                            +-- tts-relay(:3006)
                                            +-- 前端(:3110)

当前实现:
  管理器自动打开 http://localhost:3010
            +-- server.py(:3010) [单进程合并]
                   +-- LLM API (远程,替代qwen_server)
                   +-- 嵌入式前端 (embedded_ui.py)
                   +-- WebSocket游戏引擎
  另备: meoo_frontend(:3015) [React版,需npm run dev]
